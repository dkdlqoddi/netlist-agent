## 목적과 배경

반도체 설계의 기본 텍스트인 넷리스트 파일을 분석하여 핵심 회로 정보를 추출합니다.
추출한 부품과 연결 정보를 정형화된 데이터베이스에 저장할 수 있도록 중간 객체로 변환합니다.
외부 데이터베이스 서버 없이도 독립적으로 동작할 수 있도록 내장 데이터베이스를 활용합니다.
파싱 오류를 즉시 감지하여 잘못된 회로 데이터가 저장소에 유입되는 것을 방지합니다.

## 요구사항

1. 모듈(module), 신호선(wire, logic), 입출력 포트(input, output), 소자 인스턴스(instance), 핀 연결(pin), 별칭(alias) 구성요소를 파싱해야 합니다. (사용자 요청 및 1차 인터뷰 답변)
2. 시스템베릴로그(SystemVerilog)의 게이트 수준 핵심 문법을 수용해야 합니다. (1차 인터뷰 답변)
3. 추출된 회로 정보는 정규화된 테이블 구조로 데이터베이스에 저장할 수 있는 도메인 모델로 변환되어야 합니다. (2차 인터뷰 답변)
4. 별칭(alias) 구문으로 연결된 신호선들은 독립된 관계 데이터로 보존되어야 합니다. (3차 인터뷰 답변)
5. 상위 모듈과 하위 모듈이 연결된 계층형 구조의 더미 넷리스트와 파싱 실행 코드를 제공해야 합니다. (4차 인터뷰 답변)

## 동작 방식

1. 사용자가 넷리스트 파일 경로 또는 텍스트 내용을 전달하여 분석을 시작합니다.
2. 입력 텍스트에서 주석을 먼저 제거하여 유효한 회로 선언 문장들만 분리합니다.
3. 모듈 선언 구문을 만나면 새 모듈을 생성하고 입출력 포트 정보를 기록합니다.
4. 신호선 선언 구문에서 단일 비트 및 다중 비트 버스 신호선의 폭과 범위를 추출합니다.
5. 부품 소자 인스턴스 구문에서 소자 이름과 각 단자에 연결된 신호선 이름을 짝지어 기록합니다.
6. 별칭 구문이 나타나면 서로 같은 전기적 신호로 묶이는 신호선 쌍을 별도로 보존합니다.
7. 선언되지 않은 신호선이 단자에 연결된 경우 기본 1비트 신호선으로 자동 생성합니다.
8. 분석이 완료된 회로 데이터는 데이터베이스의 모듈, 신호선, 소자, 핀, 별칭 테이블에 저장됩니다.
9. 저장 중 오류가 발생하면 이전 상태로 되돌리고 실패 원인을 사용자에게 알립니다.

## 의도적 범위 제외

- 위치 기반 단자 연결: 소자의 핀 이름을 생략하고 순서대로 연결하는 문법은 모호성을 피하기 위해 지원하지 않습니다.
- 연속 할당문의 복잡한 연산식: 단순 배선을 넘어서는 산술 및 논리 연산식은 게이트 수준 넷리스트 범위를 벗어나므로 제외합니다.
- 외부 데이터베이스 서버 연동: 설치와 실행 편의를 위해 분산 데이터베이스나 외부 서버 연동은 지원하지 않습니다.
