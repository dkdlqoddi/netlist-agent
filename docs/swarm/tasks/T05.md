# T05 통합 실행 진입점 CLI 및 E2E 테스트 구현

- 역할: 통합 구현
- 웨이브: 3
- 선행: T02, T03, T04
- 대상 spec: docs/core/specs/netlist-parser.md
- 협업 스쿼드: swarm-worker (구현) ↔ swarm-verifier (검증) ↔ swarm-reviewer (리뷰)
- 소유 파일: `src/main.py` (신규), `tests/test_e2e.py` (신규)
- 참고 파일: `src/models.py`, `src/dummy_generator.py`, `src/database.py`, `src/parser.py`, `docs/core/rules.md`

## 목표

더미 넷리스트 생성, 파일 파싱, SQLite DB 적재, 회로 요약 조회를 아우르는 통합 실행 진입점 CLI 스크립트(`src/main.py`)를 구현하고, 전체 파이프라인의 E2E 통합 회귀 테스트를 작성합니다.
스펙의 요구사항 5번과 시스템 맵의 `전체 파이프라인 시연` 흐름을 완성합니다.

## 해야 할 일

1. `src/main.py` 파일을 생성하고 전체 파이프라인을 구동하는 CLI 함수를 작성합니다:
   - 인자 처리: `argparse`를 활용하여 다음 옵션을 지원합니다:
     - `--generate-dummy [경로]`: 지정된 경로(기본값 `dummy_netlist.v`)에 더미 넷리스트 파일을 생성합니다.
     - `--netlist [경로]`: 파싱할 넷리스트 파일 경로를 지정합니다. 지정하지 않으면 더미 넷리스트를 인메모리로 생성하여 즉시 사용합니다.
     - `--db [경로]`: SQLite 데이터베이스 파일 경로를 지정합니다. (기본값 `:memory:`)
     - `--summary`: 저장 후 DB의 `get_modules()`, `get_nets()`, `get_instances()`, `get_connections()`, `get_aliases()` 메서드를 호출하여 모듈 목록, 인스턴스 개수, 넷 개수, 별칭 목록을 조회하고 콘솔에 요약 출력합니다.
   - 실행 흐름:
     1. 넷리스트 내용 확보 (파일 읽기 또는 `generate_dummy_netlist()` 호출)
     2. `NetlistParser().parse_string(...)` 또는 `parse_file(...)`로 파싱 수행
     3. `NetlistDB(db_path)` 생성 및 `init_schema()` 초기화
     4. `db.save_netlist(netlist)`로 DB 저장
     5. `--summary` 옵션 시 모듈별 통계 및 회로 요약 리포트 출력
     6. 정상 완료 시 종료 코드 0, 실패 시 오류 출력 후 종료 코드 1 반환
2. `tests/test_e2e.py`에 더미 생성기부터 파서, 데이터베이스 저장 및 조회까지 이어지는 전체 워크플로우를 테스트하는 E2E 테스트 스위트를 작성합니다.

## 협업 프로토콜

1. 구현(`swarm-worker`) 완료 후 `send_message`로 `swarm-verifier`에게 `[PHASE: VERIFY_REQUEST]`를 전송합니다.
2. `swarm-verifier`는 검증 명령(`pytest tests/test_e2e.py`)을 실행하고 실패 시 에러 요약 로그를 담아 `[PHASE: VERIFY_RESULT] FAIL`을 회신하며, 성공 시 `[PHASE: VERIFY_RESULT] PASS`를 회신합니다. 실패 시 `swarm-worker`가 코드를 수정하고 재검증을 요청합니다.
3. 검증 통과 시 `swarm-worker`는 `send_message`로 `swarm-reviewer`에게 `[PHASE: REVIEW_REQUEST]`를 전송합니다.
4. `swarm-reviewer`는 git diff를 검토하여 `docs/core/rules.md` 불변 규칙 및 spec 충족 여부를 확인하고, 수정 사항이 있으면 `[PHASE: REVIEW_FEEDBACK]`을 전달하고 정합성이 확인되면 `APPROVAL (LGTM)`을 회신합니다.
5. 상호 피드백은 최대 3턴 이내에 수렴해야 하며, 3턴 초과 시 작업을 중단하고 `docs/swarm/results/T05.md`의 `## 막힌 것`에 원인을 기록한 뒤 상태를 실패로 마감합니다.
