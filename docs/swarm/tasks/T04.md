# T04 SystemVerilog 게이트 레벨 넷리스트 파서 구현

- 역할: 파서 구현
- 웨이브: 2
- 선행: T01
- 대상 spec: docs/core/specs/netlist-parser.md
- 협업 스쿼드: swarm-worker (구현) ↔ swarm-verifier (검증) ↔ swarm-reviewer (리뷰)
- 소유 파일: `src/parser.py` (신규), `tests/test_parser.py` (신규)
- 참고 파일: `src/models.py`, `docs/core/rules.md`, `docs/core/specs/netlist-parser.md`

## 목표

SystemVerilog 게이트 수준 넷리스트 파일을 읽어 `Netlist` 도메인 객체로 변환하는 `NetlistParser` 클래스를 순수 Python 표준 라이브러리로 구현합니다.
스펙의 요구사항 1번, 2번, 3번, 4번과 엣지케이스(주석 전처리, 암시적 와이어 생성, 빈 핀 연결, 이스케이프 식별자)를 완벽히 처리합니다.

## 해야 할 일

1. `src/parser.py` 파일을 생성하고 `NetlistParser` 클래스를 구현합니다:
   - 전처리: 정규식을 사용하여 한 줄 주석(`//...`) 및 블록 주석(`/* ... */`)을 제거합니다.
   - 이스케이프 식별자 처리: 역슬래시(`\`)로 시작하고 공백 문자로 끝나는 SystemVerilog 이스케이프 식별자(`\bus[0]_reg `)를 온전히 단일 식별자로 인식하여 보존합니다.
   - `parse_string(self, content: str) -> Netlist`:
     - 세미콜론(`;`) 단위로 명령문을 분리하되, ANSI 스타일(`module <name> (input ..., output ...);`)과 Non-ANSI 스타일(`module <name> (a, b); input a; output b;`) 포트 선언 문법을 모두 수용합니다.
     - `input [msb:lsb] <names>;`, `output [msb:lsb] <names>;` 포트 방향 및 폭을 파싱합니다.
     - `wire [msb:lsb] <names>;`, `logic [msb:lsb] <names>;` 신호선 선언문에서 신호선 객체를 생성합니다.
     - 소자 인스턴스화 구문 `<cell_type> <inst_name> (.PIN(NET), .PIN2(NET2), .Z());`에서 이름 기반 핀 연결 및 빈 핀을 파싱합니다.
     - 인스턴스 핀에 연결된 신호선이 기존에 wire, logic 또는 모듈 포트(input/output)로 이미 선언되지 않은 신호선인 경우, 자동으로 1비트 기본 와이어(`is_implicit=True`)를 생성하여 모듈의 wires 목록에 등록합니다.
     - `alias <net_a> = <net_b>;` 구문에서 별칭 객체를 생성하여 모듈에 추가합니다.
     - `endmodule` 키워드를 만나면 모듈 파싱을 완료하고 모듈 목록에 등록합니다.
   - `parse_file(self, filepath: str) -> Netlist`: 파일을 열어 내용을 읽고 `parse_string()`을 호출하여 결과를 반환합니다.
2. `tests/test_parser.py`에 단일 모듈, 계층형 모듈, ANSI/Non-ANSI 포트 선언, wire/logic 버스 신호, 빈 핀, alias 구문, 이스케이프 식별자(`\bus[0]_reg `), 암시적 신호선 생성 및 주석 제거에 대한 단위 테스트들을 작성합니다.

## 협업 프로토콜

1. 구현(`swarm-worker`) 완료 후 `send_message`로 `swarm-verifier`에게 `[PHASE: VERIFY_REQUEST]`를 전송합니다.
2. `swarm-verifier`는 검증 명령(`pytest tests/test_parser.py`)을 실행하고 실패 시 에러 요약 로그를 담아 `[PHASE: VERIFY_RESULT] FAIL`을 회신하며, 성공 시 `[PHASE: VERIFY_RESULT] PASS`를 회신합니다. 실패 시 `swarm-worker`가 코드를 수정하고 재검증을 요청합니다.
3. 검증 통과 시 `swarm-worker`는 `send_message`로 `swarm-reviewer`에게 `[PHASE: REVIEW_REQUEST]`를 전송합니다.
4. `swarm-reviewer`는 git diff를 검토하여 `docs/core/rules.md` 불변 규칙 및 spec 충족 여부를 확인하고, 수정 사항이 있으면 `[PHASE: REVIEW_FEEDBACK]`을 전달하고 정합성이 확인되면 `APPROVAL (LGTM)`을 회신합니다.
5. 상호 피드백은 최대 3턴 이내에 수렴해야 하며, 3턴 초과 시 작업을 중단하고 `docs/swarm/results/T04.md`의 `## 막힌 것`에 원인을 기록한 뒤 상태를 실패로 마감합니다.
