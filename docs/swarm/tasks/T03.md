# T03 SQLite 스키마 및 DB 저장소 구현

- 역할: DB 구현
- 웨이브: 2
- 선행: T01
- 대상 spec: docs/core/specs/netlist-parser.md
- 협업 스쿼드: swarm-worker (구현) ↔ swarm-verifier (검증) ↔ swarm-reviewer (리뷰)
- 소유 파일: `src/database.py` (신규), `tests/test_database.py` (신규)
- 참고 파일: `src/models.py`, `docs/core/rules.md`, `docs/core/specs/netlist-parser.md`

## 목표

파싱된 넷리스트 도메인 모델(Netlist, Module, Port, Wire, Instance, PinConnection, Alias)을 SQLite 관계형 데이터베이스에 구조화하여 저장하고 조회하는 `NetlistDB` 클래스를 구현합니다.
외래키 제약조건(`PRAGMA foreign_keys = ON;`), 단일 파일 단위의 원자적 트랜잭션 및 일괄 삽입(`executemany`) 원칙을 만족합니다.
스펙의 요구사항 3번, 4번 및 결정 기록의 정규화 테이블 구조를 충족합니다.

## 해야 할 일

1. `src/database.py` 파일을 생성하고 `NetlistDB` 클래스를 구현합니다:
   - `__init__(self, db_path: str = ":memory:")`: 데이터베이스 연결 객체를 생성하고 `PRAGMA foreign_keys = ON;`을 실행합니다.
   - `init_schema(self) -> None`: 다음 6개 정규화 테이블 DDL을 생성합니다:
     - `modules`: `id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT UNIQUE NOT NULL`
     - `ports`: `id INTEGER PRIMARY KEY AUTOINCREMENT, module_id INTEGER NOT NULL, name TEXT NOT NULL, direction TEXT NOT NULL, width INTEGER DEFAULT 1, msb INTEGER DEFAULT 0, lsb INTEGER DEFAULT 0, FOREIGN KEY(module_id) REFERENCES modules(id) ON DELETE CASCADE, UNIQUE(module_id, name)`
     - `nets`: `id INTEGER PRIMARY KEY AUTOINCREMENT, module_id INTEGER NOT NULL, name TEXT NOT NULL, data_type TEXT NOT NULL, width INTEGER DEFAULT 1, msb INTEGER DEFAULT 0, lsb INTEGER DEFAULT 0, is_implicit INTEGER DEFAULT 0, FOREIGN KEY(module_id) REFERENCES modules(id) ON DELETE CASCADE, UNIQUE(module_id, name)`
     - `instances`: `id INTEGER PRIMARY KEY AUTOINCREMENT, module_id INTEGER NOT NULL, name TEXT NOT NULL, cell_type TEXT NOT NULL, FOREIGN KEY(module_id) REFERENCES modules(id) ON DELETE CASCADE, UNIQUE(module_id, name)`
     - `pins`: `id INTEGER PRIMARY KEY AUTOINCREMENT, instance_id INTEGER NOT NULL, pin_name TEXT NOT NULL, net_name TEXT, FOREIGN KEY(instance_id) REFERENCES instances(id) ON DELETE CASCADE`
     - `aliases`: `id INTEGER PRIMARY KEY AUTOINCREMENT, module_id INTEGER NOT NULL, net_a TEXT NOT NULL, net_b TEXT NOT NULL, FOREIGN KEY(module_id) REFERENCES modules(id) ON DELETE CASCADE`
   - `save_netlist(self, netlist: Netlist) -> None`: 전체 저장을 하나의 트랜잭션으로 처리하며, 예외 발생 시 `conn.rollback()`을 호출하고 오류를 다시 발생시킵니다.
   - 조회 편의 메서드 구현:
     - `get_modules(self) -> list[dict]`: 모듈 전체 목록 반환 (`[{"id": int, "name": str}]`)
     - `get_module(self, name: str) -> dict | None`: 단일 모듈 정보 반환 (`{"id": int, "name": str}`)
     - `get_nets(self, module_name: str) -> list[dict]`: 모듈의 신호선 목록 반환 (`[{"name": str, "data_type": str, "width": int, "is_implicit": bool}]`)
     - `get_instances(self, module_name: str) -> list[dict]`: 모듈의 소자 목록 반환 (`[{"name": str, "cell_type": str}]`)
     - `get_connections(self, module_name: str) -> list[dict]`: 모듈 내 핀 연결 목록 반환 (`[{"instance_name": str, "cell_type": str, "pin_name": str, "net_name": str}]`)
     - `get_aliases(self, module_name: str) -> list[tuple[str, str]]`: 모듈의 별칭 목록 반환 (`[(net_a, net_b)]`)
     - `close(self) -> None`: DB 연결을 닫습니다.
2. `tests/test_database.py`에 인메모리 SQLite 연결을 통한 DDL 생성, Netlist 객체 적재, 외래키 무결성 검증, `get_modules()`, `get_nets()`, `get_connections()` 조회 메서드 정확성 및 오류 시 롤백 테스트를 작성합니다.

## 협업 프로토콜

1. 구현(`swarm-worker`) 완료 후 `send_message`로 `swarm-verifier`에게 `[PHASE: VERIFY_REQUEST]`를 전송합니다.
2. `swarm-verifier`는 검증 명령(`pytest tests/test_database.py`)을 실행하고 실패 시 에러 요약 로그를 담아 `[PHASE: VERIFY_RESULT] FAIL`을 회신하며, 성공 시 `[PHASE: VERIFY_RESULT] PASS`를 회신합니다. 실패 시 `swarm-worker`가 코드를 수정하고 재검증을 요청합니다.
3. 검증 통과 시 `swarm-worker`는 `send_message`로 `swarm-reviewer`에게 `[PHASE: REVIEW_REQUEST]`를 전송합니다.
4. `swarm-reviewer`는 git diff를 검토하여 `docs/core/rules.md` 불변 규칙 및 spec 충족 여부를 확인하고, 수정 사항이 있으면 `[PHASE: REVIEW_FEEDBACK]`을 전달하고 정합성이 확인되면 `APPROVAL (LGTM)`을 회신합니다.
5. 상호 피드백은 최대 3턴 이내에 수렴해야 하며, 3턴 초과 시 작업을 중단하고 `docs/swarm/results/T03.md`의 `## 막힌 것`에 원인을 기록한 뒤 상태를 실패로 마감합니다.
