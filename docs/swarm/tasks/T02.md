# T02 계층형 더미 넷리스트 생성기 구현

- 역할: 더미 생성
- 웨이브: 1
- 선행: 없음
- 대상 spec: docs/core/specs/netlist-parser.md
- 협업 스쿼드: swarm-worker (구현) ↔ swarm-verifier (검증) ↔ swarm-reviewer (리뷰)
- 소유 파일: `src/dummy_generator.py` (신규), `tests/test_dummy_generator.py` (신규)
- 참고 파일: `docs/core/rules.md`, `docs/core/specs/netlist-parser.md`

## 목표

반도체 회로의 계층 구조(상위 모듈 및 하위 모듈들)와 구성요소(module, wire, input, output, pin, logic, alias)를 포함하는 실제와 유사한 더미 SystemVerilog 넷리스트 텍스트를 생성하는 모듈을 구현합니다.
스펙의 요구사항 1번, 2번, 4번, 5번을 충족하기 위해 문자열 반환 및 파일 저장 인터페이스를 모두 제공합니다.

## 해야 할 일

1. `src/dummy_generator.py` 파일을 생성하고 다음 함수들을 구현합니다:
   - `generate_dummy_netlist() -> str`: 계층 구조를 갖춘 더미 넷리스트 텍스트를 반환합니다. ANSI 스타일 포트 선언(`module <name> (input ..., output ...);`)을 적용합니다:
     - 하위 모듈 1: `full_adder` (input a, input b, input cin, output sum, output cout / 내부 wire 선언 / XOR, AND, OR 게이트 인스턴스)
     - 하위 모듈 2: `dff_reg` (input clk, input rst_n, input d, output q / DFF 게이트 인스턴스)
     - 최상위 모듈: `chip_top` (input clk, input rst_n, input [3:0] data_in, output [3:0] data_out / wire [3:0] int_sum, logic [3:0] int_reg / `full_adder` 4개 인스턴스 / `dff_reg` 4개 인스턴스 / `alias` 구문: `alias int_net_a = int_net_b;` / 이름 기반 핀 연결 `.A(net), .B(net), .Z()` 빈 핀 포함 / 이스케이프 식별자 `\bus[0]_reg ` 포함 / 주석 포함)
   - `write_dummy_netlist_file(filepath: str) -> str`: 지정된 경로에 더미 넷리스트 파일을 기록하고 저장 경로를 반환합니다.
   - `main(argv=None) -> int`: `--output <path>` 인자를 받아 파일로 저장하거나, 인자가 없으면 표준 출력으로 내용을 출력합니다. `--dry-run` 옵션을 지원하여 파일 생성 없이 성공 코드 0을 반환합니다.
2. `tests/test_dummy_generator.py`를 생성하고 생성된 넷리스트 문자열에 `full_adder`, `dff_reg`, `chip_top`, `wire`, `logic`, `alias`, `.Z()`, `\bus[0]_reg ` 키워드가 누락 없이 포함되어 있는지 검증하는 단위 테스트를 작성합니다.

## 협업 프로토콜

1. 구현(`swarm-worker`) 완료 후 `send_message`로 `swarm-verifier`에게 `[PHASE: VERIFY_REQUEST]`를 전송합니다.
2. `swarm-verifier`는 검증 명령(`pytest tests/test_dummy_generator.py`)을 실행하고 실패 시 에러 요약 로그를 담아 `[PHASE: VERIFY_RESULT] FAIL`을 회신하며, 성공 시 `[PHASE: VERIFY_RESULT] PASS`를 회신합니다. 실패 시 `swarm-worker`가 코드를 수정하고 재검증을 요청합니다.
3. 검증 통과 시 `swarm-worker`는 `send_message`로 `swarm-reviewer`에게 `[PHASE: REVIEW_REQUEST]`를 전송합니다.
4. `swarm-reviewer`는 git diff를 검토하여 `docs/core/rules.md` 불변 규칙 및 spec 충족 여부를 확인하고, 수정 사항이 있으면 `[PHASE: REVIEW_FEEDBACK]`을 전달하고 정합성이 확인되면 `APPROVAL (LGTM)`을 회신합니다.
5. 상호 피드백은 최대 3턴 이내에 수렴해야 하며, 3턴 초과 시 작업을 중단하고 `docs/swarm/results/T02.md`의 `## 막힌 것`에 원인을 기록한 뒤 상태를 실패로 마감합니다.
